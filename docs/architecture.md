# Карта систем

Статус каждой подсистемы помечен честно. `[нет]` значит, что кода не существует —
не «спроектировано», а именно нет. Не додумывать по этому файлу.

## Граница «наш код ↔ Godot»

Ключевое правило проекта. Наш код **не живёт** внутри дерева Godot:

```bash
scons custom_modules=../modules   # модули подхватываются снаружи
```

`godot/` остаётся чистым upstream-checkout'ом на теге. Это даёт контроль над движком без ежемесячной
боли мержа. Патч внутрь `godot/` разрешён только через ADR в `docs/decisions/` — с фиксацией, что
именно и почему нельзя было сделать модулем.

**Отвергнутая альтернатива:** копировать модули в `godot/modules/`, как принято в туториалах.
Отвергнуто: тогда обновление Godot требует ручного разбора конфликтов в нашем же коде, а `git status`
перестаёт различать наше и чужое. См. ADR-0002.

## Как прибор опрашивает железо

Путь найден и проверен компиляцией; **патчей внутрь `godot/` не потребовалось**.

- **Vulkan:** `RenderingDevice::get_singleton()->get_context_driver()` → проверка
  `OS::get_current_rendering_driver_name() == "vulkan"` → `static_cast` к
  `RenderingContextDriverVulkan` → `physical_device_get(0)` → `vkEnumerateDeviceExtensionProperties`.
  Версия API и имя устройства спрашиваются у `RenderingDevice`, а не пересчитываются (PRACTICES §1.6).
  `dynamic_cast` **отвергнут**: Godot своим стилем RTTI не использует.
- **OpenXR:** `OpenXRAPI::is_extension_supported()` — **private**, дотянуться нельзя. Штатный путь —
  подкласс `OpenXRExtensionWrapper`, возвращающий карту «имя расширения → `bool *`»; рантайм сам
  проставляет флаги. Регистрация обязана быть на уровне `MODULE_INITIALIZATION_LEVEL_SERVERS`
  (как в `modules/openxr/register_types.cpp:154`): на `SCENE` уже поздно, флаги останутся `false`
  и прибор молча соврёт «расширений нет».
- Флаг обёртки означает «запрошено И доступно», а не «рантайм знает расширение». В отчёте
  называть именно так.

## Ограничения платформы

Здесь **не должно быть чисел**, кроме подтверждённых. Всё измеренное живёт в
`docs/hardware-profile.md` и берётся оттуда.

Подтверждено по вендорским источникам (не на железе):

- Quest 3 / XR2 Gen 2: 2 производительных + 4 энергоэффективных ядра, TDP 4–6 Вт, 8 ГБ RAM,
  2064×2208 на глаз. CPU — узкое место, не GPU.
- **Eye tracking отсутствует.** Gaze-интеракция возможна только как head-gaze.
- ОС при перегреве принудительно сбрасывает частоту к базовым 72 Гц. Движок обязан адаптироваться.
- Драйверы сообщают Vulkan 1.3.295 — **не 1.4**, вопреки исходному исследованию.

Разбор того, что в исследовании неверно: `docs/research/source-review.md`.

## Когда обновлять этот файл

- Появился новый модуль в `modules/` или подсистема сменила статус с `[нет]`.
- Изменилась граница «наш код ↔ Godot» — например, появился первый патч внутрь `godot/`.
- Принят ADR, меняющий слои (рендер-путь, формат проекта, экспорт).
- Сменилась версия базы Godot.
- Прибор опроверг любое из «подтверждено по вендорским источникам» выше.
- Появился второй путь, которым сцена попадает на экран (например, отдельный путь для редактора).
