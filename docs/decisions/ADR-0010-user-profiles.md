# ADR-0010: профили пользователей и области данных

- **Дата:** 2026-09-19
- **Статус:** **принято, код есть** (этапы B, C; 2026-09-19), на шлеме проверен только перенос настроек
  и наборы по вводу (сессия 12). Проекты (этап E) — ссылки есть, содержимого нет до ADR о формате.
- **Решает:** владелец проекта.
- **Связан с:** ADR-0008 (шар-меню: настройки, ввод руками), ADR-0011 (аккаунты и секреты).

## Контекст

До сессии 11 у приложения был один файл настроек `user://sphere_settings.cfg` и один файл избранного — на
всех людей и на оба способа ввода. Сессия 11 (2026-09-19) впервые провела меню руками, и владелец
попросил:

- разные настройки для рук и контроллеров, переключаемые вместе со способом ввода;
- профили пользователей, выбираемые в настройках: сведения о человеке, профили настроек, проекты,
  подключаемые аккаунты;
- продумать, что у каждого своё (рост, комната), а что общее (системные каталоги).

Сверка с документацией Meta (правило 8): Quest держит до четырёх системных аккаунтов, и данные приложений у
каждого свои.

## Решение

1. **Три области данных:** устройство, пользователь, сессия; внутри пользователя — профиль по способу
   ввода. Правило разбора и полная таблица — `docs/design/user-profiles.md`, раздел 2.
2. **Профиль пользователя** хранит: личное (имя, цвет, язык, PIN по желанию), тело (рост, измеренная
   высота глаз, сидя/стоя), места (отпечаток игровой зоны, рабочая точка, поле под якоря Ф3), профили
   настроек ввода, избранное и недавнее, ссылки на проекты, аккаунты.
3. **Общими для устройства** остаются системные каталоги, список профилей, секрет устройства,
   идентификаторы OAuth-клиентов, измеренные бюджеты, журнал (с id профиля в каждой строке).
4. **Настройки меню по способу ввода.** У каждой настройки — область `input`, `user` или `session`.
   Решение владельца 2026-09-19: сейчас **все** настройки меню — `input`; механизм `user` готов и
   проверяется, кандидаты — в таблице раздела 4 проектного документа. Профиль рук при первом
   переключении — копия контроллеров.
5. **Ручной выбор источника ввода — только сессия.** Выбранные руки при выключенном отслеживании рук
   заперли бы приложение насовсем (шаг 1к, пункт 2).
6. **Профиль указывается по случайному id**, не по имени; раскладка — `user://profiles/<id>/`.
7. **Миграция без потерь:** старые файлы становятся профилем «Основной» и переименовываются в
   `*.migrated`, не удаляются.
8. **Ведущая рука** хранится, но не показывается, пока меню не умеет жить в правой руке.

## Отвергнутые альтернативы

- **Только системные аккаунты Quest.** Разделение уже есть, но не покрывает людей под одним
  аккаунтом и PCVR, где системного разделения нет. Профили приложения ему не противоречат: внутри
  каждого системного аккаунта — свой список профилей.
- **Один файл настроек на всех.** Так было до сессии 11: руки и контроллеры спорят за одни числа, люди —
  за одно избранное.
- **Разные системные каталоги у разных людей.** Дублирует ассеты и прячет файлы, видимые только из
  чужого профиля.
- **Имя как идентификатор профиля.** Имя меняется, и ссылки из журнала и «последнего активного»
  рвались бы.
- **Рост из измеренной высоты глаз.** Соотношение не измерено; рост вводится отдельно.

## Последствия, которые надо принять

- Все места, писавшие `user://sphere_settings.cfg`, начинают писать в файл активного профиля ввода.
- Журнал получает две колонки — «ввод» и «профиль»; старые строки файла на шлеме остаются в прежнем
  формате (заголовок пишется в начале каждой сессии).
- Выгрузка копирует дерево профилей без секретов.
- Папка «Проекты» пуста до ADR о формате проекта.

## Когда пересматривать

- Появился формат проекта — ссылки получают содержимое.
- Сессия, пройденная обоими способами ввода, показала совпадение значений — настройка переходит в `user`.
- Меню научилось жить в правой руке — ведущая рука показывается и применяется.
- Появились пространственные якоря (Ф3) — места узнаются по ним, а не по отпечатку зоны.
