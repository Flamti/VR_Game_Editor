# ADR-0011: подключаемые аккаунты и хранение секретов

- **Дата:** 2026-09-19
- **Статус:** **принято**, кода нет (этап D — `docs/design/user-profiles.md`, раздел 9).
- **Решает:** владелец проекта.
- **Связан с:** ADR-0010 (профили пользователей).

## Контекст

Владелец (2026-09-19): профиль пользователя хранит подключаемые аккаунты — Google Drive, Claude,
ChatGPT и подобные; делать сразу полностью, с OAuth; PIN профиля — по желанию.

Условия платформы:

- на Quest нет Google Play Services, а вход Google во встроенном веб-view запрещён самим Google;
- у Godot 4.7 есть `HTTPRequest` (TLS), `Crypto` (HMAC, случайные байты), `AESContext` (только ECB и
  CBC), `HashingContext`; доступа к Android Keystore из GDScript нет;
- в пресете экспорта шар-меню нет разрешения на интернет.

Сверка с документацией (правило 8, 2026-09-19):

- **Google, поток для устройств с ограниченным вводом** (developers.google.com/identity/protocols/oauth2/limited-input-device):
  клиент типа «TVs and Limited Input devices»; эндпоинты `https://oauth2.googleapis.com/device/code` и
  `https://oauth2.googleapis.com/token`; для Drive разрешены только `drive.file` и `drive.appdata`; токен
  обновления выдаётся всегда.
- **Anthropic:** сторонним приложениям запрещён вход по подписке Claude.ai — только ключ API из Claude
  Console. Проверка ключа без расхода токенов — `GET /v1/models` с `x-api-key` и
  `anthropic-version: 2023-06-01`; 401 — неверный ключ, 403 — ключу запрещено.
- **OpenAI:** «Sign in with ChatGPT» не даёт стороннему приложению доступа к модели — только ключ API;
  проверка — `GET /v1/models` с `Authorization: Bearer`.

## Решение

1. **Google Drive — поток «код устройства».** Шлем показывает адрес и код, человек входит с телефона или
   компьютера; приложение опрашивает эндпоинт токена с интервалом из ответа и обрабатывает
   `authorization_pending`, `slow_down` (+5 с), `access_denied`, `expired_token`. Области:
   `openid email drive.file`. Хранится токен обновления; токен доступа — только в памяти.
2. **Claude и ChatGPT — ключи API.** Ввод текстом на панели (замаскирован) или импорт из файла в
   собственном каталоге приложения; файл после импорта удаляется. Проверка — запрос списка моделей,
   токены не тратятся. Модель Claude по умолчанию в профиле — `claude-opus-5`.
3. **Секреты — в `user://profiles/<id>/secrets.enc`:** AES-256-CBC, затем HMAC-SHA256 по шифротексту
   (encrypt-then-MAC). Ключи шифрования и MAC выводятся из одного корня:
   - у профиля с PIN — PBKDF2-HMAC-SHA256(PIN, соль профиля);
   - без PIN — из секрета устройства.

   **Число итераций PBKDF2 — измерить на шлеме** (цель — вход не дольше 300 мс); до замера числа в коде
   нет.
4. **Секреты никогда** не пишутся в журнал, logcat и выгрузку; проверка выгрузки краснеет, если
   `secrets.enc` или строка ключа туда попали.
5. **Идентификаторы OAuth-клиентов** — в `projects/sphere_menu/secrets/oauth_clients.cfg`: файл вне
   git (`.gitignore`), в APK — через `include_filter`. У клиента «TVs and Limited Input devices» секрет
   по документации Google не конфиденциален, но в репозиторий он всё равно не попадает.
6. **Разрешение на интернет** — в пресете экспорта; проверяется манифестом собранного APK
   (`aapt2 dump xmltree`), а не строкой пресета (ловушка 12).
7. **Сеть — через подменяемый транспорт.** В проверках вместо сети — готовые ответы; поток «код
   устройства» — чистый конечный автомат.

## Отвергнутые альтернативы

- **OAuth Google через браузер Quest с возвратом на `127.0.0.1`** (локальный сервер в приложении).
  Возможно, но не проверено на Quest: браузер — отдельное приложение, доступность петлевого адреса между
  ними и поведение при сворачивании приложения неизвестны. Поток «код устройства» не требует возврата
  в приложение вовсе.
- **Встроенный веб-view для входа Google.** Запрещено Google.
- **Вход по подписке Claude.ai.** Запрещено Anthropic для сторонних приложений.
- **Секреты открытым текстом в профиле.** Любой, кто наденет шлем или получит выгрузку, получил бы
  ключи.
- **AES-GCM.** В `AESContext` Godot его нет; CBC с отдельным HMAC даёт ту же проверку целостности.
- **Android Keystore.** Надёжнее ключа устройства в `user://`, но нужен Java-плагин. Отложено как
  усиление; менять формат `secrets.enc` при этом не придётся — меняется только источник корневого ключа.

## Последствия, которые надо принять

- Без PIN секреты защищает только песочница Android; **отладочный APK читается через `run-as`**.
- PIN из 4 цифр перебирается офлайн, если файл уже вынут; растущая задержка защищает только ввод в шлеме.
- Нужны действия владельца: проект Google Cloud, OAuth-клиент «TVs and Limited Input devices», экран
  согласия в режиме Testing с его адресом среди тестовых пользователей.
- Сессия на шлеме с аккаунтами требует сети и настоящих ключей.

## Когда пересматривать

- Появился Java-плагин для Android Keystore.
- Anthropic или OpenAI открыли сторонний вход по подписке.
- Drive понадобился шире `drive.file` (например, открыть файлы, созданные не приложением) — поток «код
  устройства» этого не даёт, нужен другой вход.
- Проверка на шлеме показала, что петлевой возврат из браузера Quest работает надёжно.
